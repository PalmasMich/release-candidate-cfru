# Release Candidate — Post-Starter Crash Diagnostic Plan

Observed on first private full build:
- ROM boots;
- player reaches custom starter choice;
- crash occurs after selecting a starter.

## Confirmed

- Chapter 1 preflight passes.
- Full DPE -> CFRU -> RC build succeeds.
- FireRed `givemon` bytecode emitted by the RC compiler is 15 bytes, matching the upstream macro layout:
  - opcode
  - species u16
  - level u8
  - item u16
  - unused u32
  - unused u32
  - unused u8
- CFRU `NUM_SPECIES` is extended through RC reserved IDs.
- RC learnset entries exist for Tartrek, Frobyte, Emberfox and Mistrillo.
- DPE overlay registers RC base stats, names, front/back sprites, icons, palettes and coordinates.
- DPE Species -> National Dex table is sized through `NUM_SPECIES`, but RC entries are currently zero/default.

## Source-level root cause found (runtime confirmation pending)

The combined call chain is now explicit:

1. the custom event script executes `givemon`;
2. CFRU `ScriptGiveMon` creates and adds the creature;
3. on success it immediately calls `SetMonPokedexFlags`;
4. that function passes `SpeciesToNationalPokedexNum(species)` to the seen/caught flag routines;
5. the DPE table previously left every RC slot at the designated-array default `0`.

Passing National Dex `0` into the flag-setting path is invalid and occurs at the exact observed post-choice boundary. DPE now assigns unique entries 899–902 and emits matching Species -> National Dex, Pokédex data and description records transactionally. CFRU validates the selected sibling DPE checkout before its build.

This closes the source-level defect, but it does **not** mark the crash fixed. The three-starter clean-save smoke matrix below remains mandatory on a private ROM.

## Leading hypotheses

1. ~~A runtime table used immediately after `givemon` is not populated for RC species despite the global size extension.~~ Source defect corrected; private runtime confirmation pending.
2. A custom species pointer/table generated by DPE is not the table CFRU runtime actually reads after the combined build.
3. A post-`givemon` event command is reached with corrupted interpreter state due to a linker/pointer mismatch.
4. Starter-specific art/data can trigger a runtime read after party creation.
5. The crash is species-dependent rather than common to all three starters.

## Diagnostic build strategy

Create temporary diagnostic script variants, never master:

Stage 1:
- `givemon`
- immediate `end`
- no flag;
- no message.

If stable, Stage 2:
- add starter flag.

If stable, Stage 3:
- add confirmation message.

If stable, Stage 4:
- restore normal release/flow.

This binary-searches the crash boundary without changing species IDs.

Do not call the crash fixed until a clean private ROM:

- shows their confirmation dialogue;
- permits opening the party screen;
